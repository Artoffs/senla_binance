# Binance Price Tracker Service

Сервис для периодического получения средней цены торговой пары с публичного API биржи Binance (`GET /api/v3/avgPrice`), сохранения истории в PostgreSQL и предоставления аналитических данных через REST API.

---

## Быстрый запуск (Docker Compose)

Для запуска всего окружения (PostgreSQL + приложение) выполните в корне проекта:

```bash
docker compose up --build -d
```

После запуска сервис будет доступен по адресу: `http://localhost:8080`.
Просмотр логов приложения:
```bash
docker logs -f senla-binance-app
```

Остановка сервиса:
```bash
docker compose down
```

---

## Локальный запуск (без Docker для приложения)

1. Поднимите локальную БД PostgreSQL (например, через Docker):
   ```bash
   docker compose up postgres -d
   ```
2. Запустите приложение через Maven:
   ```bash
   mvn spring-boot:run
   ```
3. Запуск модульных и интеграционных тестов (требуется запущенный Docker для Testcontainers):
   ```bash
   mvn clean test
   ```

## Поддерживаемые переменные окружения

Настройки сервиса можно переопределять через переменные окружения (в `docker-compose.yml` или системе):

| Переменная | Значение по умолчанию                      | Описание |
| :--- |:-------------------------------------------| :--- |
| `BINANCE_POLL_INTERVAL` | `PT30S`                                    | Интервал опроса API Binance в формате ISO-8601 (например, `PT10S`, `PT1M`) |
| `BINANCE_SYMBOL` | `BNBUSDT`                                  | Отслеживаемая торговая пара на бирже Binance |
| `BINANCE_BASE_URL` | `https://api.binance.com`                  | Базовый URL API биржи Binance |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/binance` | JDBC URL для подключения к базе данных PostgreSQL |
| `SPRING_DATASOURCE_USERNAME` | `postgres`                                 | Имя пользователя базы данных |
| `SPRING_DATASOURCE_PASSWORD` | `postgres`                                 | Пароль пользователя базы данных |

## Описание REST API и примеры вызовов

Все параметры дат (`from`, `to`) принимаются в формате **ISO-8601** в часовом поясе UTC (например: `2026-11-06T00:00:00Z`).

### 1. Получение последней актуальной записи
Возвращает самую свежую сохраненную котировку.

**Запрос:**
```bash
curl -X GET "http://localhost:8080/api/v1/prices/latest"
```

**Пример ответа (`200 OK`):**
```json
{
  "symbol": "BNBUSDT",
  "price": 598.45000000,
  "fetchedAt": "2026-11-06T10:15:30Z"
}
```

---

### 2. Расчет средней цены за период
Возвращает среднюю арифметическую цену по всем сохраненным записям в заданном интервале `[from, to]`.

**Запрос:**
```bash
curl -X GET "http://localhost:8080/api/v1/prices/average?from=2026-11-01T00:00:00Z&to=2026-11-07T00:00:00Z"
```

**Пример ответа (`200 OK`):**
```json
{
  "averagePrice": 596.125
}
```

---

### 3. Получение истории записей за период с пагинацией
Возвращает страницу сохраненных записей за интервал `[from, to]`, отсортированных по убыванию времени получения.

**Параметры запроса:**
* `from` — начало периода (ISO-8601)
* `to` — конец периода (ISO-8601)
* `page` — номер страницы, начиная с `0` (по умолчанию `0`)
* `size` — размер страницы (по умолчанию `20`)

**Запрос:**
```bash
curl -X GET "http://localhost:8080/api/v1/prices?from=2026-11-01T00:00:00Z&to=2026-11-07T00:00:00Z&page=0&size=20"
```

**Пример ответа (`200 OK`):**
```json
{
  "items": [
    {
      "symbol": "BNBUSDT",
      "price": 598.45000000,
      "fetchedAt": "2026-11-06T10:15:30Z"
    }
  ],
  "page": 0,
  "size": 20,
  "totalElements": 135,
  "hasNext": true
}
```

---

### 4. Вычисление тренда цены за период
Определяет направление движения цены (`UPWARD`, `DOWNWARD`, `FLAT`), сравнивая первую и последнюю записи в указанном интервале `[from, to]`.

**Запрос:**
```bash
curl -X GET "http://localhost:8080/api/v1/prices/trend?from=2026-11-01T00:00:00Z&to=2026-11-07T00:00:00Z"
```

**Пример ответа (`200 OK`):**
```json
{
  "symbol": "BNBUSDT",
  "start_date": "2026-11-01",
  "end_date": "2026-11-07",
  "trend": "UPWARD"
}
```

## Обработка ошибок и ограничений (Rate Limits)
* Ошибки сети или временная недоступность API Binance перехватываются в планировщике (`PriceScheduler`), логируются и не прерывают выполнение следующих циклов опроса.
* При получении статусов `429 Too Many Requests` или `418 IP Auto-banned` от Binance сервис приостанавливает запросы на время, указанное в заголовке `Retry-After`.
* Защита от дублирования данных обеспечивается проверкой времени закрытия окна (`closeTime`) и уникальным ограничением на уровне БД.
